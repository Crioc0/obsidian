# Контейнер Promise в ФП


## Что это? (Определение)
Этот контейнер добавляет данным одно из трех состояний: Rejected, Fullfilled или Pending. Promise инкапсулирует доступ к данным, доступ к сырым данным закрыт API контейнера
Promise можно рассматривать как [[Монады|монаду]] Результат монадического вычисления может привести к созданию контейнера с состоянием, отличным от исходного




## Зачем это нужно? (Применение)
Для работы с данными, которые еще не получены

## Как это работает? (Принцип)
При работе с Promise часто получаются функции вида (...)=>Promise. Из этих цепочек часто выстраивают цепочку вычислений
```js
fs.readFile("user.json") 
.then(JSON.parse) 
.then(data => (data.age++, data)) 
.then(JSON.stringify) 
.then(str => fs.writeFile("user.json", str)) 
.catch(console.error);
```
Если в .then(JSON.parse) если JSON.parse запаникует, то новый контейнер будет в Rejected и все последующие .then не будут выполнять свои фунарги. 

Для этого в then есть своя логика.
1) Если при вызове фунарга выбрасывается исключение, оно перехватывается и упаковывается как Rejected
2) Результат работы фунарга обрабатывается через Promise.resolve: если там не Promise, то он упаковывается как Fulfilled
