# Контейнер в виде функции


## Что это? (Определение)
Функици - тоже контейнеры. Они - это абстракции над вычислениями.

Например,
```js
add2 = (x) => x + 2
```
 Аргумент x является контекстом, а вычисление – «эффектом» Чтобы извлечь значение из контекста – надо вызвать функцию Чтобы упаковать в контейнер – упаковать в функцию Например, 
 ```js
  cnst = (value) => (_) => value; cnst(42); // (_) => 42
 ```


## Зачем это нужно? (Применение)
Функции действительно можно рассматривать, как обычные контейнеры И наделить их стандартными интерфейсами функтора, аппликативного функтора и монады. Можно создать композицию

## Как это работает? (Принцип)
По контракту, map принимает некоторую «обычную» функцию и вызывает её со значением «извлеченным» из нашего контейнера Результат этого вызова нужно будет упаковать обратно в контейнер Поэтому реализовать map для функций можно так:
```js
fmap = (ctx, fn) => /* Упаковываем */ (x) => fn( /* Извлекаем */ ctx(x))
```
Благодаря этому получается композиция

Можно усовершенствовать реализацию fmap
```js
function fmap(ctx, fn) { 
	return (...args) => call(fn, call(ctx, ...args)); 
} 
function sum(a, b) { 
	return a + b; 
} 

function multiply(a, b) { 
	return a * b; 
} 

console.log(fmap(sum, multiply)(2, 5)(10)); // 70
```

На основе можно сделать compose
```js
function compose(...fns) { 
	let fn = fns.pop(); 
	while (fns.length > 0) { 
	fn = fmap(fn, fns.pop());
	} 
	return fn; 
} 
// (...args) => add42(mult10(sum(...args))) 
console.log(compose(add42, mult10, sum)(2, 3)); // 92
```
Можно создать функцию при помощи аппликативного функтора, именно тогда раскрывается мощь композиции, ведь любую функцию со множеством аргументов можно представить как функцию в контексте другой функции,
Например, 
```js
salaryRecipe = (config, age, bonus) => age * 1000 + bonus 
```
Можно представить как: 
```js
(config) => (age, bonus) => age * 1000 + bonus
```

```js
const config = { 
	userName: "Анна", 
	userAge: 25, 
	bonus: 1000 
}; 

const getUserAge = config => config.userAge; 

const getBonus = config => config.bonus; 

const salaryRecipe = (config, age, bonus) => age * 1000 + bonus; 

const getSalary = ap(ap(salaryRecipe, getUserAge), getBonus);
 
console.log(getSalary(config)); // 26000
```

У нас есть функция в контексте конфига: 
```js
salaryRecipe = (config, age, bonus) => age * 1000 + bonus
```
 И мы применяем к ней другие функции в контексте: **getUserAge** и **getBonus** В итоге получаем такое: 
 ```js
  getSalary = (config) => ( (age, bonus) => age * 1000 + bonus )(getUserAge(config), getBonus(config))
 ```
Наши функции простые, без побочных эффектов и не связаны друг с другом.
Данный паттерн называется «Читатель»
