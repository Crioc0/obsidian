# Тип number и стандарт IEEE 754

Тип `number` в JavaScript реализован по стандарту **IEEE 754-2008** (двойная точность, binary64), нативно поддерживается процессором. Этот стандарт определяет, как числа с плавающей точкой хранятся в памяти и как выполняются операции над ними.

Структура 64-битного числа (double):

```
64 бита (8 байт):
┌───────────────────────────┐
│ 1 бит │ 11 бит │ 52 бита  │
│ знак  │ порядок│ мантисса │
└───────────────────────────┘
```

- **Знак (sign)** — 0 для положительных, 1 для отрицательных
- **Порядок (exponent)** — 11 бит, смещённый на 1023 (для хранения знака)
- **Мантисса (mantissa/fraction)** — 52 бита, хранит значащие цифры числа

Несмотря на размер мантисcы в 52 бита в number можно безопасно хранить целое до 2^53-1
далее начинаются переполнение и потеря точности. Лишний бит потому что число хранится в нормальной форме 1.

Потеря точности происходит по двум причинам:

1. **Целые числа вне безопасного диапазона** — соседние числа становятся неразличимыми.
2. **Дробные числа** — большинство десятичных дробей не могут быть представлены точно в двоичной системе.

```js
console.log(0.1 + 0.2);                      // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);              // false
console.log((0.1 + 0.2).toFixed(1) === 0.3); // true — но это костыль
```

В стандарте IEEE 754 существует как положительный ноль `+0`, так и отрицательный ноль `-0`. В большинстве операций они ведут себя одинаково, но есть различия:

```js
console.log(0 === -0);         // true (сравнение не различает)
console.log(Object.is(0, -0)); // false (Object.is различает)

console.log(1 / 0);            // Infinity
console.log(1 / -0);           // -Infinity
```

Разрядность числа влияет на точность представления:

- **32-битные float (single precision):** точность ~7–8 десятичных знаков
- **64-битные double (double precision):** точность ~15–16 десятичных знаков

JavaScript использует 64-битные double, что даёт достаточно высокую точность, но не решает проблему десятичного представления.
