# MessagePack

MessagePack — это бинарный аналог JSON. Он использует те же структуры данных (объекты, массивы, строки, числа), но кодирует их в более компактные байты.

**Принцип работы:** Вместо текстовых разделителей (фигурные скобки, двоеточия, запятые) MessagePack использует специальные байты-префиксы, которые обозначают тип и размер следующих данных.

**Таблица типов MessagePack (упрощённо):**

|Тип|Байт префикса|Что означает|
|---|---|---|
|fixmap|0x80-0x8F|Объект с 1-15 парами|
|fixstr|0xA0-0xBF|Строка длиной 1-31 байт|
|fixarray|0x90-0x9F|Массив с 1-15 элементами|
|positive fixint|0x00-0x7F|Маленькое положительное число|

**Пример кодирования объекта:** `{"age": 30, "name": "Alex"}`

В JSON: 17 байт В MessagePack: 12 байт

Что лежит в этих 12 байтах:

```
0x82 — fixmap с 2 элементами
0xA3 — fixstr длиной 3 байта (ключ "age")
0x61 0x67 0x65 — "age"
0x1E — positive fixint (30)
0xA4 — fixstr длиной 4 байта (ключ "name")
0x6E 0x61 0x6D 0x65 — "name"
0xA4 — fixstr длиной 4 байта (значение "Alex")
0x41 0x6C 0x65 0x78 — "Alex"
```

**Использование MessagePack:**

```js
import { unpack, pack } from "msgpackr";

const data = {
    name: "Alice",
    age: 30,
    isStudent: false
};

// Сериализация
const packed = pack(data);

// Десериализация
const unpacked = unpack(packed);
```

**Почему MessagePack не вытеснил JSON?**

1. **Инструментарий.** JSON поддерживается "из коробки" в браузерах, а для MessagePack нужно подключать библиотеку.
2. **Отладка.** Бинарный файл нельзя открыть и понять, что там внутри.
3. **Безопасность.** Некоторые бинарные форматы могут быть уязвимы для атак (например, "billion laughs attack").
4. **Достаточность JSON.** Для большинства задач JSON достаточно быстр и компактен.

MessagePack — это бинарный формат сериализации, который сохраняет структуру JSON, но упаковывает данные в компактные байты. Его главное преимущество — **плавный переход с JSON без изменения архитектуры**.

1. Простой переход с JSON: копирование/вставка структуры

MessagePack спроектирован так, чтобы быть **полным аналогом JSON** в бинарном мире. Типы данных совпадают один-к-одному:

| JSON тип              | MessagePack тип | Примечание                   |
| --------------------- | --------------- | ---------------------------- |
| Объект `{key: value}` | Map             | Порядок ключей сохраняется   |
| Массив `[1,2,3]`      | Array           | Сохраняется порядок          |
| Строка `"hello"`      | String          | UTF-8 кодировка              |
| Число `123`           | Int / Float     | Компактное хранение (varint) |
| `true` / `false`      | True / False    | 1 байт                       |
| `null`                | Nil             | 1 байт                       |

2. Плюсы для бекенд-бекенд общения (сервис ↔ сервис)

При общении между микросервисами MessagePack даёт значительные преимущества.

**Преимущества:**

| Характеристика                      | JSON                      | MessagePack                               | Выигрыш                          |
| ----------------------------------- | ------------------------- | ----------------------------------------- | -------------------------------- |
| **Размер данных**                   | Большой                   | На 30-50% меньше                          | Меньше трафика, быстрее передача |
| **Скорость парсинга**               | Медленный (анализ текста) | Быстрый (чтение байт)                     | В 2-5 раз быстрее                |
| **Потребление памяти при парсинге** | Высокое (создание строк)  | Низкое (работа с буферами)                | Меньше GC                        |
| **Типизация**                       | Строки, числа, null       | Расширенная (бинарные данные, расширения) | Гибкость                         |

3. MessagePack в BFF (Backend For Frontend)

BFF — это прослойка между бекендом и фронтендом. Здесь MessagePack даёт интересные возможности.

**Преимущества для BFF:**

- **Меньше трафика между BFF и бекендом** — особенно важно в облачных средах (плата за трафик)
- **Ниже задержки** — быстрее парсинг на BFF
- **Меньше GC** — BFF обрабатывает тысячи запросов в секунду, лишние аллокации вредны
- **Единый интерфейс** — BFF не нужно менять код, если бекенд переходит с JSON на MessagePack
