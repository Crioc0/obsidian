# CSV
CSV — простейший текстовый формат для табличных данных. Каждая строка — одна запись, столбцы разделены запятыми (или другими разделителями: точка с запятой, табуляция).

**Идеальный CSV:**

```csv
name,age,city
Alice,30,Moscow
Bob,25,St.Petersburg
Charlie,35,Kazan
```

**Проблемы CSV на практике:**

1. **Нет единого стандарта.** В разных странах используют разные разделители (в России часто точка с запятой, потому что запятая — это десятичный разделитель в числах).

2. **Проблема с экранированием символов.** Что делать, если в тексте есть запятая или кавычки?

```csv   
  name,description
   Alice,Works at "Google"
   Bob,Loves pizza, beer and wine   
```
   
 Этот CSV сломан, потому что:

- В первой строке кавычки внутри описания не экранированы
- Во второй строке запятая внутри описания воспринимается как разделитель столбцов

**Решение — цитирование и экранирование:** По негласному стандарту (RFC 4180):

- Поля с разделителями или кавычками заключаются в двойные кавычки
- Кавычки внутри поля дублируются (`"` → `""`)

```csv
   name,description  
  Alice,"Works at ""Google"""
  Bob,"Loves pizza, beer and wine"
```
  
  
3. **Нет поддержки вложенных структур.** Нельзя представить иерархические данные (объект внутри объекта).
  
4. **Проблемы с кодировками и переносами строк.** Перенос строки внутри поля — ещё одна головная боль.
  

#### Сильные стороны CSV: потоковая работа, экономичность и табличные данные


CSV (Comma-Separated Values) часто недооценивают, считая его "слишком простым". Однако у него есть уникальные преимущества, которые делают его лучшим выбором для многих задач.

1. Потоковая работа "из коробки"

CSV — это **строчно-ориентированный формат**. Это позволяет обрабатывать файлы любой размерности без загрузки в память целиком.

**Как это работает:**

- Конец строки (`\n`) — это естественный разделитель записей
- Парсер может читать файл построчно, не дожидаясь окончания
- Для обработки следующей строки не нужны данные о предыдущих
- Не нужно загружать все данные для сериализации

**Сравнение с другими форматами:**

| Формат   | Можно читать построчно?    | Почему                                 |
| -------- | -------------------------- | -------------------------------------- |
| **CSV**  | ✅ Да                       | Каждая строка — самодостаточная запись |
| **JSON** | ❌ Нет (без библиотек)      | Весь документ — один массив или объект |
| **XML**  | ❌ Нет (без сложных трюков) | Корневой элемент охватывает всё        |

2. Экономичность: сжатие часто не нужно

CSV настолько компактен, что для многих задач **не требует дополнительного сжатия**. Это экономит CPU на кодирование/декодирование gzip/zlib.

**Почему CSV такой экономичный:**

| Формат               | На 1000 записей (id, name, age, city) | Относительный размер |
| -------------------- | ------------------------------------- | -------------------- |
| **CSV**              | ~30 KB                                | 1x                   |
| **JSON с массивом**  | ~45 KB                                | 1.5x                 |
| **JSON с объектами** | ~65 KB                                | 2.17x                |
| **XML**              | ~120 KB                               | 4x                   |

3. Идеальное решение для табличной информации

Любые данные, которые можно представить в виде таблицы (строки и столбцы), отлично ложатся в CSV.

**Примеры идеального использования CSV:**

- Экспорт банковских выписок
- Отчёты по продажам
- Данные аналитики (Google Analytics export)
- Каталоги товаров (название, цена, остаток, поставщик)
- Списки пользователей (id, email, дата регистрации, статус)
4. Идеальное решение для логов и метрик

Логи — это как раз та история, где CSV раскрывается полностью:

- **Логи растут непрерывно** — CSV можно дописывать построчно
- **Нужно обрабатывать гигабайты** — потоковая работа решает проблему
- **Формат лога часто меняется** — в CSV можно добавить колонку, старые строки просто будут иметь пустое значение
- **Логи анализируют утилитами** — grep, awk, cut, sort прекрасно работают с CSV
5. Совместимость с табличными редакторами

CSV можно открыть в любом табличном редакторе "из коробки":

- **Microsoft Excel** — просто перетащить файл
- **Google Sheets** — импорт за секунду
- **LibreOffice Calc** — родной формат
- **Базы данных** — импорт/экспорт через CSV

**Реальный кейс:** Бизнес-аналитик просит выгрузку данных. Вы даёте ему CSV. Он открывает в Excel, строит сводную таблицу, создаёт график — и счастлив.

**Если дать JSON:** Аналитик позвонит и скажет: "Что мне с этим делать? Где Excel?"

6. Простота генерации и парсинга

CSV настолько прост, что его можно генерировать и читать без библиотек (хотя для сложных случаев библиотеки нужны).
