# Преобразование в байткод

Чтобы не парсить каждый раз инструкции из строи, можно предварительно транслировать исходный код в удобный формат. Обычно используется специально разработанный поз задачу бинарный код, также называемый байткодом. В отличии от машинного, байткод не поддерживается процессором, и для его исполнения нужен интерпретатор. Интерпретатор байткода называется виртуальной машиной.

Чтобы еще ускорить процесс интерпретации, можно «запомнить» единожды сгенерированный для файла байткод и при последующих запусках брать сразу его. Такой подход называется кэшированием байткода

Байткод — это абстракция, придуманная для переносимости. Разные процессоры (x86, ARM, RISC-V) понимают разные наборы инструкций. Если бы процессоры исполняли байткод Java напрямую, то:

- Байткод пришлось бы менять при смене архитектуры
- Процессоры стали бы сложнее и дороже
- Переносимость исчезла бы

Поэтому байткод исполняется виртуальной машиной, а VM уже транслирует его в машинный код конкретного процессора.
