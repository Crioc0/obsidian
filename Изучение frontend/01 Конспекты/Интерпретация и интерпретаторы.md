# Интерпретация и интерпретаторы

**Интерпретатор** — это программа, которая читает исходный код и выполняет его построчно, без предварительной компиляции в машинный код.

Процесс разбора исходного кода называется парсингом

**Плюсы интерпретации:**

- Не нужно ждать компиляции (быстрый старт)
- Легче писать REPL (Read-Eval-Print Loop)
- Проще переносимость (нужен только интерпретатор)
- Можно выполнять код, который генерируется на лету (eval)

**Пример интерпретатора на JavaScript:**

```js
function interpret(program) {
	const lines = program.split('\n');
	for (const line of lines) {
		if (line.startsWith('print')) {
			const message = line.slice(6);
			console.log(message);
		}
// ... другие команды
	}
}
```

**Минусы интерпретации:**

- Медленнее, чем скомпилированный код
- Требуется интерпретатор для запуска
- Каждый раз при запуске нужно разбирать исходный код
- Ошибки типов проявляются только во время выполнения

![[Разница между компилятором и интерпретатором.png]]

Интерпретатор – это программа, которая «понимает» код на исходном языке и умеет его исполнять на конкретном устройстве. Сам интерпретатор – это программа, которая уже в свою очередь может исполняться процессором «напрямую» (это не всегда так). Если «интерпретатор» транслирует исходный код в машинный, а далее он исполняется уже самое машиной, то это уже компиляция. Просто в этом случае фаза компиляции делается неявно перед запуском программы
