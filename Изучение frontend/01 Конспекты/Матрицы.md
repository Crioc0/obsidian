# Матрицы

Массив представляет собой линейную последовательность элементов, но вместо линейного доступа можно создать N-мерное пространство, обращение к которым будет обращаться с помощью указания нескольких координат. Самый простой способ - создание двухмерной или трехмерной матрицы.

![[Двухмерная и трехмерное пространство.png]]

### Двухмерная матрица

Под капотом двухмерной матрицы лежит обычный массив, емкость массива равна произведению строк и столбцов.

Чтобы вычислить индекс конкретной ячейки, нужно **номер строки умножить на количество столбцов в массиве и прибавить номер столбца**. При таком расположении будет выгоднее проходить матрицу по строкам. Формула, оптимизированная под столбцы **номер столбца умножить на количество строк в массиве и прибавить номер строки**

```ts
class Matrix {
  readonly rows: number;
  readonly cols: number;
  readonly #data: T[];
  constructor(rows: number, cols: number) {
    this.rows = rows;
    this.cols = cols;
    this.#data = new Array(rows * cols).fill(undefined);
  }
  get(row: number, col: number): T {
    return this.#data[this.#getIndex(row, col)];
  }
  set(row: number, col: number, value: T) {
    this.#data[this.#getIndex(row, col)] = value;
  }
  #getIndex(row: number, col: number) {
    return row * this.cols + col;
  }
}
```

### Трехмерная матрица

Для трёхмерного пространства добавляется глубина (depth). Ёмкость массива становится произведением `rows × cols × depth`.

Можно добавить параметр `order`, который определяет порядок укладки элементов в памяти (row-major, col-major, depth-major).

```ts
enum MatrixOrder {
  RowMajor,
  ColumnMajor,
  DepthMajor,
}
class Matrix3D {
  readonly rows: number;
  readonly cols: number;
  readonly depths: number;
  readonly #data: T[];
  readonly #order: MatrixOrder;
  constructor(
    rows: number,
    cols: number,
    depths: number,
    order = MatrixOrder.RowMajor,
  ) {
    this.rows = rows;
    this.cols = cols;
    this.depths = depths;
    this.#order = order;
    this.#data = new Array(rows * cols * depths).fill(undefined);
  }
  get(row: number, col: number, depth: number): T {
    return this.#data[this.#getIndex(row, col, depth)];
  }
  set(row: number, col: number, depth: number, value: T) {
    this.#data[this.#getIndex(row, col, depth)] = value;
  }
  #getIndex(row: number, col: number, depth: number) {
    switch (this.#order) {
      case MatrixOrder.ColumnMajor:
        return col * this.rows * this.depths + row * this.depths + depth;
      case MatrixOrder.DepthMajor:
        return depth * this.rows * this.cols + row * this.cols + col;
      default:
        return row * this.cols * this.depths + col * this.depths + depth;
    }
  }
}

```

### Применение матриц

- Линейная алгебра (транспонирование, сложение матриц)
- Компьютерная графика (матрицы трансформации, системы координат)
- Машинное обучение и ИИ (тензоры)
- Обработка изображений (пиксели как матрица RGB)

### Совместимость с линейным представлением

Матрица — это чистый view над данными. Например, можно взять буфер пикселей от Canvas (`getImageData`), интерпретировать его как матрицу (ширина × высота), обработать и вернуть обратно. Данные не меняются — меняется только способ доступа.

### Оптимизация под кэш-память

Если данные хранятся в том же порядке, в котором мы их обходим, эффективность кэша максимальна. Элементы физически лежат рядом → в кэш-линию попадают соседние элементы.

### Матрица — это просто массив с новыми контрактами

Матрица не требует новой памяти. Это те же данные, но с методами `get(row, col)` и `set(row, col, value)`. Удобство представления — главный плюс.

### Эффективность матриц

- Хорошая работа с кэш-памятью
- Минимальная нагрузка на сборщик мусора (нет вложенных объектов)
- Компактное хранение

### Матрица vs массив массивов

|Характеристика|Матрица (плоский массив)|Массив массивов (вложенный)|
|---|---|---|
|**Размер строк**|Фиксированный (все строки одинаковы)|Может быть разным|
|**Память**|Одна аллокация|N+1 аллокаций (массив + каждый подмассив)|
|**Кэш**|Отличная локальность|Плохая локальность (указатели)|
|**Сериализация**|Простая (один буфер)|Сложная (нужно кодировать длины)|
|**GC нагрузка**|Минимальная|Высокая (много объектов)|

### Константная сложность сериализации для типизированных массивов

Типизированный массив (например, Uint8Array) можно записать на диск или отправить по сети как один блок байт. Парсинг тоже не нужен — можно создать view прямо поверх полученного буфера.

Для обычного массива массивов сериализация требует обхода всех элементов и кодирования структур.
