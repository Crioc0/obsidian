# Проблема нативного JSON
Стандартный `JSON.parse()` и `JSON.stringify()` имеют фундаментальное ограничение: они работают только с **полностью загруженным документом**. Весь JSON-файл должен быть прочитан целиком, прежде чем начнётся его парсинг или сериализация.

**Почему это проблема:**

1. **Огромное потребление памяти.** Если у вас есть JSON-файл размером 2 ГБ (например, экспорт базы данных или лог-файл), `JSON.parse()` выделит память под весь файл плюс под результирующий объект/массив. Итоговое потребление может достигать 4-6 ГБ и более.

```js
   // Плохо для больших файлов — весь файл загружается в память целиком
   const fs = require('fs');
   const hugeData = JSON.parse(fs.readFileSync('2gb-file.json', 'utf8'));
  // Память: 2 ГБ (файл) + объекты в JS (~3-4 ГБ) = 5-6 ГБ
  // Приложение упадёт с "JavaScript heap out of memory"
```  
2. **Невозможность потоковой обработки.** Системы, которые обрабатывают бесконечные потоки данных (логи, показания сенсоров, финансовые котировки в реальном времени), не могут использовать нативный JSON, потому что поток никогда не заканчивается.
3. **Задержка до первого результата.** При передаче JSON по сети парсер не может начать обработку, пока не получит последний байт. Для больших данных это создаёт задержку в несколько секунд или даже минут.

**Пример проблемы: сервер генерирует гигантский массив**

```js
  // Сервер отправляет массив из 10 миллионов чисел
   // Клиент не сможет обработать ни одно число, пока не получит весь массив целиком
   // Это создаёт огромную задержку и потребление памяти
   const response = await fetch('/api/big-data');
  const hugeArray = await response.json(); // Ждём завершения передачи
   // Только теперь можно начать обработку
   hugeArray.forEach(item => process(item));
```

**Сценарии, где это критично:**

| Сценарий              | Проблема                      | Последствия                       |
| --------------------- | ----------------------------- | --------------------------------- |
| **Экспорт БД**        | Миллионы записей в JSON       | Нехватка памяти, падение процесса |
| **Логи сервера**      | Файлы логов растут непрерывно | Нельзя распарсить лог за раз      |
| **API с пагинацией**  | Клиент ждёт весь ответ        | UI "зависает" на время загрузки   |
| **Генерация отчётов** | Формирование JSON в памяти    | Out of memory на сервере          |
