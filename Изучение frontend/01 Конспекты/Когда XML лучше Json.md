# Когда XML лучше Json
Несмотря на то, что JSON вытеснил XML из многих областей (особенно веб-API), существуют сценарии, где XML остаётся незаменимым или даже предпочтительным выбором.

1. Языки разметки (Markup Languages)

XML изначально создавался как язык разметки, а не просто формат данных. Это его "родная" стихия.

**Проблема JSON для разметки:** JSON не предназначен для смешивания текста с разметкой. Любой текст с разметкой внутри JSON превращается в кошмар.

2. Векторная графика (SVG)

SVG — это векторный формат, основанный на XML. Попытка представить SVG в JSON привела бы к катастрофе.

**Почему SVG не переходит на JSON:**

- **Инструментарий:** Браузеры умеют рендерить SVG "из коробки", есть редакторы (Inkscape, Adobe Illustrator)
- **Смешивание с HTML:** SVG можно вставлять прямо в HTML-документ без конвертации
- **CSS-стилизация:** К элементам SVG можно применять CSS
- **Иерархия и группировка:** `<g>` и `<defs>` естественно выражаются в XML
3. Сложные конфигурации десктопных и мобильных приложений

Многие платформы используют XML для конфигурации интерфейсов (Android, WPF, Qt).

**Преимущества XML в этом сценарии:**

- **Декларативность:** Описание интерфейса похоже на структуру DOM
- **Пространства имён:** `android:` отделяет атрибуты платформы от кастомных
- **Валидация через схемы:** IDE подсказывает доступные атрибуты
- **Инструменты визуального редактора:** Легко парсить и генерировать

**JSON не прижился здесь**, потому что отсутствие комментариев в стандартном JSON усложняет документирование, а иерархия атрибутов и дочерних элементов становится неочевидной.

4. Научные и технические форматы

Многие форматы в науке, технике и промышленности используют XML из-за строгой валидации и самодокументируемости.

**Примеры таких форматов:**

- **MathML** — математические формулы (используется в Wikipedia и научных статьях)
- **MusicXML** — нотная грамота
- **Collada** — обмен 3D-моделями
- **DITA** — техническая документация
- **Office Open XML** (DOCX, XLSX, PPTX) — форматы Microsoft Office
5. Смешивание нескольких языков/пространств имён

XML поддерживает пространства имён, позволяя смешивать в одном документе данные из разных словарей без конфликтов.

**JSON не имеет механизма пространств имён.** Если вам нужно объединить данные из разных систем, либо ключи будут конфликтовать, либо придётся использовать костыли вроде `"math:formula"`, что нарушает читаемость.

6. Строгая валидация и контракты

Для сложных распределённых систем (банкинг, авиабилеты, государственные сервисы) нужна строгая проверка данных на соответствие схеме.

**Возможности XSD, которых нет в JSON Schema (или они реализованы хуже):**

- **Строгие типы данных** (date, time, duration, anyURI)
- **Регулярные выражения** для проверки форматов
- **Уникальность ключей и ссылки** между элементами (как внешние ключи в БД)
- **Наследование типов** (extension, restriction)
7. XSLT — мощная трансформация

XML имеет XSLT — язык преобразования XML-документов в другие XML, HTML, текст. Это встроенный механизм, не требующий написания кода на Python/JS.

В мире JSON нет инструмента такой же мощности и распространённости.
