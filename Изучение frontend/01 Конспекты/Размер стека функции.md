# Размер стека функции
Размер стека ограничен для более эффективной работы и не меняется, поэтому по сути работу стека можно описать следующим образом:
1) Выделяется память под стек достаточно большого размера
2) При достижении конца стека выделим искдючительную ситуацию - переполнение стека (или UB)
3) Каждый вызов стека на функции будет иметь свою память на стеке, именуемую кадром.
4) Для добавления новых значений нужно знанть размер добавляемых данных.
5) Когда функция завершается, она должна передвинуть вершину стека в то место, где она была
## Сегмент стека поддерживается аппаратно
Процессор имеет два специальных регистра для работы с памятью как со стеком. Регистр RBP содержит адрес начала актуального кадра стека (граница кадра). Регистр RSP содержит адрес актуальной вершины стека. Благодаря этим регистрам, работа с сегментом стека становится ещё эффективнее. Но сама реализация функций остаётся задачей компилятора или среды исполнения. В языках ассемблера функций нет, поэтому сам разработчик решает как реализовать нужное ему поведение

Различные ОС имеют разные значения размера стека по умолчанию В Linux 8 МБ для основного потока, а в Windows 1 МБ Можно ограничивать размер стека с помощью параметров компиляции В JS размером стека управляет виртуальная машина В Node.js можно управлять флагом --stack-size
