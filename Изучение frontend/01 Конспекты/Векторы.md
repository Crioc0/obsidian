# Векторы

### Как делают массивы расширяемыми

Классический массив нельзя расширить. Решение:

1. Создать новый массив большего размера (обычно в 1.5-2 раза)
2. Скопировать все элементы из старого массива
3. Освободить старый массив
4. Заменить ссылку на новый

### Структура данных Вектор

Вектор — это структура из трёх полей:

|Поле|Описание|
|---|---|
|`length`|Сколько элементов фактически вставлено|
|`capacity`|Максимальное количество элементов (размер выделенного буфера)|
|`ptr` (указатель)|Ссылка на сырой массив|

Когда `length === capacity` — нужно выделить новый буфер большей ёмкости.

### Можно ли не копировать память?

В низкоуровневых языках есть операция `realloc`, которая пытается расширить память без копирования (если рядом есть свободное место). В JavaScript при работе с ArrayBuffer можно использовать `resize`, но это не гарантирует избежания копирования.

### Минимизация аллокаций

Если заранее известна или минимальная ёмкость — задавайте её сразу. Это одна из важнейших оптимизаций.

**Пример: разница между `push` и предварительным выделением памяти**

|Подход|Время (условное)|
|---|---|
|`for + push` (частые расширения)|4x|
|`new Array(n) + заполнение по индексу`|1x (базовый)|

### Вектор — фундаментальная структура

Вектор лежит в основе многих других структур:

- **Изменяемые строки** (в языках, где строки можно менять) — это вектор символов
- **Хеш-таблицы** — под капотом используют вектор для хранения бакетов

### Обычные массивы в JavaScript — это векторы?

В JavaScript обычные массивы могут быть:

- **Packed arrays** — плотные, без дырок (близки к вектору)
- **Holey arrays** — с дырками (всё ещё могут быть оптимизированы)
- **Dictionary arrays** — выродились в хеш-таблицу (уже не вектор)

### Что происходит при удалении элементов?

Спецификация ECMAScript **не регламентирует**, должна ли память массива уменьшаться при удалении элементов. Это зависит от реализации конкретного движка (V8, SpiderMonkey, JavaScriptCore и т.д.).

**Что говорят спецификации:** никаких требований к освобождению памяти нет.

**Как ведут себя реальные движки (на примере V8):**

|Тип массива|Поведение при удалении|
|---|---|
|**Packed array (плотный)**|В какой-то момент может переаллоцироваться в меньший размер (если свободной памяти слишком много)|
|**Holey array (с дырками)**|Буфер обычно не уменьшается|

### Самостоятельная реализация вектора для типизированных массивов

В JavaScript нет встроенного динамического массива для типизированных данных. Можно реализовать свой Vector, который:

- Хранит ArrayBuffer и DataView
- Управляет capacity и length
- При расширении создаёт новый буфер и копирует данные

### Паттерн амортизированного роста

Идея: увеличивать ёмкость не на фиксированную величину, а в геометрической прогрессии (обычно в 2 раза). Это даёт амортизированную константную сложность вставки.

**Применения за пределами векторов:**

- **Бесконечный скролл:** первый запрос 10 элементов, потом 20, потом 40...
- **Повторные сетевые запросы:** 1s → 2s → 4s → 8s (экспоненциальная задержка)

### Что делать, если память закончилась (Out of Memory)

- **Вариант 1 (безопасный):** вернуть ошибку, не добавлять элемент
- **Вариант 2 (паника):** завершить программу
- **Вариант 3 (перезапись):** если очередь фиксированного размера — перезаписывать старые данные

Встраиваемые системы часто используют фиксированные размеры — там нет динамической памяти.
