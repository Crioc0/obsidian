# Процессы в ОС

Любая современна многозадачная ОС использует систему процессов. Процесс представляет собой единицу исполнения любой программы. Процесс состоит минимум из одного потока исполнения (инструкции нашей программы) и набора ресурсов. Ресурсами являются адресное пространство памяти, файловые дескрипторы и другое

## Каждая программа запускает процесс

При этом если вы запустите два раза одну и ту же программу, то будет создано два разных процесса. Некоторые программы, например, Chrome, создают отдельный процесс для каждой вкладки. Такой подход обеспечивает лучшую безопасность за счёт изоляции процессов, но повышает общее потребление памяти. Процессы могут общаться друг с другом с помощью механизмов ОС, сети или файловой системы

**Процесс** — это экземпляр выполняющейся программы. У процесса есть:

- своё **адресное пространство** (набор виртуальных адресов, которые он может использовать, организованный в виде нескольких сегментов);
- один или несколько **потоков** (нитей выполнения);
- набор прав и идентификаторов (PID, пользователь, группа);
- контекст выполнения (значения регистров, состояние стека).

С точки зрения ОС, процесс — это единица владения ресурсами, но не обязательно единица выполнения.

## Межпроцессное взаимодействие (IPC)

Поскольку процессы изолированы, им нужны механизмы для обмена данными. Основные способы межпроцессного взаимодействия:

- **Каналы (pipes)** — однонаправленная передача данных между родственными процессами.
- **Именованные каналы (FIFO)** — работа через файловую систему.
- **Сигналы (signals)** — асинхронные уведомления (например, `SIGKILL`).
- **Сокеты (sockets)** — обмен данными между процессами на одной или разных машинах.
- **Разделяемая память (shared memory)** — самый быстрый способ, несколько процессов отображают одну область физической памяти в свои адресные пространства.
- **Очереди сообщений (message queues)**.

## Потоки (Threads)

Процесс может содержать несколько **потоков** — лёгких единиц выполнения, которые разделяют адресное пространство процесса. У каждого потока есть свой стек и набор регистров, но общие код, глобальные данные, куча и файловые дескрипторы.

**Преимущества потоков:**

- создание и переключение между потоками дешевле, чем между процессами;
- простота обмена данными — потоки одного процесса видят память друг друга.

**Недостатки:**

- один поток может разрушить данные всего процесса;
- нужна синхронизация (мьютексы, семафоры, критические секции).


## Адресное пространство процесса и стартовые регистры

Когда процесс создаётся, ОС не выделяет ему один непрерывный блок памяти. Вместо этого ОС создаёт для процесса **таблицы страниц** и формирует **набор виртуальных областей** (VMA — Virtual Memory Areas в Linux, секции в Windows). Каждая область имеет свои права доступа и назначение.

ОС создаёт отображения (memory mappings) для каждого сегмента из исполняемого файла (ELF/PE/Mach-O) плюс дополнительные области для стека, кучи и разделяемых библиотек. Сами виртуальные адреса не обязаны быть непрерывными — процессор и MMU скрывают разрывы через таблицы страниц, но с точки зрения программы адресное пространство _выглядит_ непрерывным в пределах доступных областей.

**Стартовые регистры** при запуске процесса (или нового потока) инициализируются следующим образом:

- **Указатель инструкции (RIP/EIP/IP)** устанавливается на точку входа. Однако это не обязательно `main`. На практике первым выполняется код **стартовой процедуры** (crt0, `_start`), которая настраивает среду (аргументы командной строки, окружение, инициализацию статических объектов в C++) и уже затем вызывает `main`.
- **Указатель стека (RSP/ESP/SP)** устанавливается на вершину только что выделенного стека. Стек — это отдельная виртуальная область со своими правами (обычно `rw-`), которая может динамически расти вниз. В конце стековой области часто размещается **защитная страница** (guard page) — при обращении к ней возникает исключение, что позволяет обнаружить переполнение стека.
