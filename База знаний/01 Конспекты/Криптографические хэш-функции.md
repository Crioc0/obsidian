# Криптографические хэш-функции

**Криптографические хэш-функции** (SHA-256, MD5, BLAKE) обладают дополнительными свойствами:

- **Однонаправленность** — по хэшу невозможно восстановить исходные данные.
- **Стойкость к коллизиям** — невозможно подобрать два разных сообщения с одинаковым хэшом.
- **Лавинный эффект** — изменение одного бита входных данных сильно меняет хэш.

Вопрос использования криптографических хэшей в хэш-таблицах — это **компромис между производительностью и безопасностью **.

**Почему обычно предпочитают некриптографические хэши (MurmurHash, xxHash, CityHash, FNV-1a):**

- Они значительно быстрее (в десятки раз).
- Для внутренних нужд программы (ключи не контролируются злоумышленником) достаточно хорошей равномерности.

**Когда нужны криптографические или рандомизированные хэши:**

- Хэш-таблица **торчит наружу** — обрабатывает ключи, поступающие от пользователя (HTTP-параметры, JSON-ключи, имена полей в форме).
- Злоумышленник может намеренно подобрать множество ключей с одинаковым хэшем, вызывая коллизии. Это приводит к деградации производительности хэш-таблицы до O(n) и может стать причиной **DoS-атаки**.

**Решения:**

1. Использовать криптографическую хэш-функцию (защита от коллизий, но медленно).
2. Использовать **рандомизированную хэш-функцию** с солью (случайное значение при запуске). Даже если сама функция не криптографическая, коллизии, подобранные для одного запуска, не сработают на другом.
3. Комбинировать: быстрый хэш + соль + защита от чрезмерно длинных цепочек (переключение на дерево при превышении порога, как в Java 8+).

**Пример из реального мира:** PHP долгое время использовал простой хэш, и это приводило к реальным DoS-атакам. Начиная с PHP 5.3.9, ввели защиту — максимальный лимит на количество ключей в одной корзине, а также рандомизированный хэш. В Python 3.3+ хэш строк рандомизирован по умолчанию (флаг `PYTHONHASHSEED`).

**Вывод:**

- Внутренние хэш-таблицы → некриптографические быстрые хэши.
- Публичные хэш-таблицы (пользовательские ключи) → рандомизированный хэш (или криптографический) + дополнительная защита от коллизий.
