# Возобновляемость итераторов

**Важно:** нет строгого контракта, что итератор после того, как вернул `done: true`, не может быть возобновлён. Хотя в большинстве случаев итераторы завершаются и последующие вызовы `next()` продолжают возвращать `{ done: true }`, это не является обязательным требованием.

Мы можем создать **возобновляемый итератор**, который после завершения (`done: true`) сбрасывает состояние и начинает заново при следующем обходе:

```js
function createRange(start, end) {
    let current = start;
    return Iterator.from({
        next() {
            if (current > end) {
                current = start; // сброс состояния!
                return {value: undefined, done: true};
            }
            return {value: current++, done: false};
        },
    });
}

const iter = createRange(1, 3);

// Первый обход
for (const num of iter) {
    console.log(num); // 1 2 3
}

// Второй обход — начался заново!
for (const num of iter) {
    console.log(num); // 1 2 3
}

// Третий обход — снова с начала!
for (const num of iter) {
    console.log(num); // 1 2 3
}
```

**Как это работает:**

1. Итератор проходит значения от `start` до `end`.
2. Когда `current > end`, он возвращает `{ done: true }`.
3. **Важно:** перед возвратом `done: true` он сбрасывает `current = start`.
4. При следующем вызове `next()` итератор снова начинает с `start`.

**Сравнение с обычным итератором:**

```js
// Обычный итератор — не возобновляется
const regularIter = [1, 2, 3][Symbol.iterator]();
for (const num of regularIter) {
    console.log(num); // 1 2 3
}
for (const num of regularIter) {
    console.log(num); // ничего не выведет — итератор завершён
}

// Возобновляемый итератор — сбрасывается после завершения
const resettableIter = createRange(1, 3);
for (const num of resettableIter) {
    console.log(num); // 1 2 3
}
for (const num of resettableIter) {
    console.log(num); // 1 2 3 — снова!
}
```

**Вывод:** нет строгого контракта, что итератор после `done: true` не может быть возобновлён. Разработчик может реализовать собственную логику сброса состояния, чтобы итератор можно было использовать повторно. Однако для большинства встроенных итераторов (массивы, Set, Map) после `done: true` дальнейшие вызовы `next()` продолжают возвращать `{ done: true }`.
