# Стратегии оптимизации объектов в V8
Внутренняя реализация объектов в движках (V8, SpiderMonkey) гораздо сложнее простой хэш-таблицы. Они используют несколько стратегий:

- **Скрытые классы (Hidden Classes)** — для объектов с фиксированной структурой.
- **Словари (Dictionary mode)** — для объектов, у которых динамически добавляются/удаляются свойства.

## Оптимизация через скрытые классы



**Скрытые классы** (также известны как «карты» или «формы») — ключевая оптимизация в V8. Идея:

- Объекты с одинаковым набором свойств (и в одинаковом порядке добавления) разделяют один скрытый класс.
- Скрытый класс хранит смещения свойств в памяти (как в структуре C).
- Доступ к свойству превращается в доступ по фиксированному смещению — очень быстро.

```js
// Объекты point1 и point2 разделяют скрытый класс
const point1 = {x: 10, y: 20};
const point2 = {x: 30, y: 40};

// Добавление нового свойства создаёт новый скрытый класс
point1.z = 50; // теперь у point1 и point2 разные скрытые классы
```

**Правила для эффективного использования скрытых классов:**

- **Инициализируйте все свойства в конструкторе** — это создаёт стабильную структуру. Если вы заранее знаете все свойства объекта, объявите их в конструкторе (даже со значениями `null` или `undefined`). Это позволяет движку создать скрытый класс с фиксированным набором свойств.
    
- **Добавляйте свойства в одном и том же порядке** — если вы создаёте несколько объектов с одинаковым набором свойств, но в разном порядке, они получат разные скрытые классы, и оптимизация не сработает.
    

```js
// Хорошо: одинаковый порядок
const p1 = {x: 10, y: 20};
const p2 = {x: 30, y: 40};
// p1 и p2 разделяют скрытый класс

// Плохо: разный порядок
const p3 = {y: 10, x: 20};
const p4 = {x: 30, y: 40};
// p3 и p4 имеют разные скрытые классы
```

- **Добавление новых свойств после создания объекта возможно** — это не запрещено и не «ломает» оптимизацию мгновенно. Однако каждое добавление нового свойства создаёт **новый скрытый класс** в цепочке. При частых добавлениях цепочка становится длинной, что снижает эффективность.

```js
const point = {x: 10, y: 20};  // скрытый класс C0
point.z = 30;                     // новый скрытый класс C1 (производный от C0)
point.color = "red";              // новый скрытый класс C2 (производный от C1)
// Доступ к свойствам всё ещё быстрее словаря, но уже не так эффективен
```

- **Избегайте `delete`** — удаление свойства переводит объект в «словарный режим» (slow mode), где доступ к свойствам осуществляется через хэш-таблицу. После этого вернуться к скрытым классам невозможно.

```js
const obj = {a: 1, b: 2, c: 3};
delete obj.b;  // объект переходит в словарный режим, оптимизация теряется
```

- **Не смешивайте типы в одном свойстве** — хранение значений разных типов в одном и том же свойстве в разных объектах также может создавать разные скрытые классы.

```js
// Хорошо: тип свойства одинаков
const p1 = {x: 10};
const p2 = {x: 20};

// Плохо: типы разные
const p3 = {x: 10};
const p4 = {x: "20"}; // другой скрытый класс
```

**Как работает цепочка скрытых классов:** V8 создаёт скрытые классы постепенно. При добавлении первого свойства создаётся C0 (пустой) и затем C1 (с первым свойством). При добавлении второго свойства — C2 (с двумя свойствами) и так далее. Объекты с одинаковой историей добавления свойств разделяют скрытые классы.
