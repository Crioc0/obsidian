# Объекты в JS
Согласно спецификации ECMAScript, объекты в JavaScript — это **ассоциативные массивы** (сопоставление ключей со значениями). При этом **любой объект** является таким ассоциативным массивом, просто способы доступа могут различаться:

- Обычные объекты `{}` — используют скобочную нотацию `obj[key]` или точечную `obj.key` (для ключей-идентификаторов).
- `Map` — тоже объект (экземпляр класса `Map`), предоставляющий ассоциативное отображение через методы `get(key)` и `set(key, value)`.
- `Set` — объект для хранения уникальных значений (ассоциативный массив, где значение равно ключу).
- Функции, массивы, встроенные объекты — также являются ассоциативными массивами и могут иметь произвольные свойства.

```js
// Обычный объект — скобочная нотация
const obj = {name: "Иван"};
console.log(obj["name"]); // "Иван"

// Map — тоже объект, но с интерфейсом через методы
const map = new Map();
map.set("name", "Иван");
console.log(map.get("name")); // "Иван"

// У Map тоже можно добавлять свойства как у обычного объекта
// (но так делать не рекомендуется — это внутреннее хранилище)
map.custom = "значение";
console.log(map.custom); // "значение"

// Set — объект для уникальных значений
const set = new Set();
set.add("Иван");
console.log(set.has("Иван")); // true
```

### Что говорит спецификация


Объект в ECMAScript — это коллекция **свойств (properties)**. Каждое свойство имеет:

- Ключ (только `string` или `Symbol`)
- Значение
- Набор атрибутов (writable, enumerable, configurable)

`Map` и `Set` не хранят свои пары ключ-значение как свойства объекта (они не перечисляются в `Object.keys()` и не видны через скобочную нотацию). Внутри у них есть **слоты** (спецификационные внутренние поля, например `[[MapData]]`), которые хранят данные. Но сами экземпляры `Map` и `Set` остаются объектами, и к ним можно добавлять обычные свойства.

Спецификация определяет **абстрактные операции** для работы с объектами: `Get`, `Set`, `HasProperty`, `Delete` и т.д. Эти операции работают с любыми объектами, включая `Map` и `Set`, но для доступа к данным `Map` используются методы, а не стандартные `Get`/`Set` свойств.

### Как реализовано на практике

Хотя спецификация говорит только про ассоциативное поведение, все современные движки (V8, SpiderMonkey, JavaScriptCore) используют **хэш-таблицы** как основу для хранения свойств объектов. Однако с мощными оптимизациями:

1. **Скрытые классы (Hidden Classes)** — для объектов с фиксированной структурой.
2. **Словарный режим (Dictionary Mode)** — для динамических объектов с частым добавлением/удалением свойств.
3. **Раздельное хранение** — числовые индексы массивов могут храниться в отдельном векторе (backing store).
4. **Инлайн-свойства (in-object properties)** — часть свойств хранится прямо в самом объекте, без обращения к хэш-таблице.

Для `Map` и `Set` движки используют специализированные структуры данных (обычно тоже хэш-таблицы), но отдельные от механизма свойств объектов. Это позволяет оптимизировать их под свои задачи (например, быстрый перебор в порядке вставки).

### Разные структуры для разных целей


В JavaScript есть несколько встроенных ассоциативных структур (все они — объекты):

|Структура|Интерфейс|Типы ключей|Порядок|Прототип|Когда использовать|
|---|---|---|---|---|---|
|`Object`|скобки / точка|строки, символы|сложный (целые индексы + порядок добавления)|есть|Простые объекты, JSON|
|`Map`|`get()`/`set()`|любые|порядок вставки|есть (но пустой)|Динамические словари|
|`WeakMap`|`get()`/`set()`|только объекты (слабые)|не перечисляем|есть|Кэши, приватные данные|
|`Set`|`add()`/`has()`|любые|порядок вставки|есть|Уникальные значения|
|`WeakSet`|`add()`/`has()`|только объекты (слабые)|не перечисляем|есть|Множества объектов без утечек|

**Вывод:** все перечисленные структуры — это объекты в смысле спецификации. Разница — в способе доступа к ассоциативным данным (скобочная нотация у обычных объектов против методов у `Map`/`Set`) и во внутреннем устройстве хранения.
