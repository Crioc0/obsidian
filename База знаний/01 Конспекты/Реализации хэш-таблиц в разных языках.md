# Реализации хэш-таблиц в разных языках
| Язык   | Ассоциативный массив | Комментарий                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------ | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Python | `dict`               | Хэш-таблица с открытой адресацией и линейным пробированием. Оптимизирована для CPython. Использует рандомизированный хэш для защиты от DoS-атак (PYTHONHASHSEED).                                                                                                                                                                                                                                                                                                                                        |
| Java   | `HashMap`            | До Java 8: метод цепочек (массив + связные списки). Java 8+: при длине цепочки более 8 элементов преобразуются в красно-чёрное дерево для улучшения производительности в худшем случае. При удалении, если размер дерева падает ниже 6, оно преобразуется обратно в список.                                                                                                                                                                                                                              |
| C++    | `std::unordered_map` | Метод цепочек (отдельные списки для каждой корзины). Стандарт не специфицирует детали реализации, но все основные компиляторы (libstdc++, libc++) используют именно цепочки. Предоставляет параметры для управления load factor и rehashing.                                                                                                                                                                                                                                                             |
| Go     | `map`                | **Swiss Table** (начиная с Go 1.24). В октябре 2024 года в Go добавлена реализация Swiss Table в пакет `internal/runtime/maps`. Использует extendible hashing с иерархической структурой (directory + таблицы) для инкрементального роста. Более ранние версии (до 1.24) использовали классический метод цепочек с бакетами (по 8 пар ключ-значение на бакет) и оверфлоу-ссылками.                                                                                                                       |
| Rust   | `HashMap`            | **Swiss Table** через крейт `hashbrown`. Начиная с Rust 1.36 стандартная библиотека использует Swiss Table. Реализация портирована из Google SwissTable (abseil). Использует открытую адресацию, контрольные байты (control bytes) и SIMD-оптимизации. Пустая таблица не выделяет память. Хэш-функция по умолчанию — `foldhash` (с версии `hashbrown` 0.16), ранее использовался SipHash 1-3 для защиты от HashDoS-атак.                                                                                 |
| PHP    | `array`              | **Ordered hash table** — классическая хэш-таблица с цепочками, но с дополнительным двусвязным списком для сохранения порядка вставки. PHP 7+ использует более компактную структуру (Bucket с 32 байтами вместо 72 в PHP 5). PHP 8+ для плотных целочисленных массивов без дырок использует **packed array** — непрерывный массив без хэш-таблицы, что даёт производительность, близкую к C-массивам. Хэш-функция для строк — DJBX33A с рандомизацией для защиты от атак. Load factor ~0.5 для rehashing. |
|        |                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
**О Swiss Table:** Изначально разработана Google для C++ (abseil / Swiss Tables). Ключевые особенности:

- **Группы по 8 или 16 слотов** — контрольные байты хранят нижние 7 бит хэша (H2) для быстрой фильтрации.
- **SIMD-инструкции** — параллельное сравнение всех байт группы за одну операцию на x86_64 (до 16 слотов) и ARM.
- **Открытая адресация** с квадратичным пробированием.
- **Высокий load factor** — до 7/8 (87.5%) до начала rehashing.
- **Компактность** — 1 байт служебной информации на запись.

**В Go** реализация Swiss Table имеет особенности, связанные с инкрементальным ростом. Вместо одной таблицы используется иерархия: directory указывает на несколько независимых таблиц, что позволяет расти без полного перехэширования всей карты.

**В Rust** `std::collections::HashMap` — это обёртка над крейтом `hashbrown`, который является портом Swiss Table. `hashbrown` также доступен как отдельный крейт для `no_std`-сред.

**О SwissTable (Rust):** Google SwissTable — это современная реализация хэш-таблицы с открытой адресацией, которая:

- Использует **SIMD-инструкции** для сканирования нескольких хэш-ячеек за одну операцию (до 16 ячеек одновременно на x86_64) [citation:1].
- Хранит **контрольные байты (control bytes)** отдельно от самих ключей/значений, что улучшает локальность памяти.
- Обеспечивает высокий коэффициент заполнения (до 7/8) при сохранении производительности.
- Потребляет всего **1 байт служебной информации на запись** (против 8 байт в старой реализации) [citation:1].

Rust не использует `hashbrown` напрямую, стандартный `std::collections::HashMap` — это обёртка над `hashbrown` с собственным хэшером. При этом `hashbrown` доступен как отдельный крейт для `no_std`-сред.
