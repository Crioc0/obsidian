# Сегмент памяти куча (heap)

У стека есть два важных ограничения - обязательное копирование при возврате значения из функции и нужно заранее знать размер, который будет занимать значение в памяти. Для обхода этих ограничений придумали другой сегмент памяти - кучу (heap). 

Кучу размещают на другом конце от стека. Это позволяет стеку и куче «расти» навстречу друг другу. Если они встретятся, то это будет UB В отличие от стека, размер кучи может меняться динамически. Но в JS он ограничен параметрами виртуальной машины Например, в Chrome это 2 гибибайта. В Node.js можно явно управлять размером кучи с помощью специальных флагов

## Контракты кучи

1) Выделить память заданного размера и вернуть указатель на первый байт (alloc)
2) Перевыделить память нового размера для уже имеющегося блока и вернуть указатель на свободный байт (realloc)
3) Освободить память по заданному указателю (free)

## Сложности реализации

Сегмент стека сделать очень просто — выделить память фиксированного размера и два специальных регистра для управления. С кучей такое сделать куда сложнее, поэтому на аппаратном уровне есть только простейшие регистры для доступа к любой ячейке памяти по её адресу. А сложный функционал — дефрагментация памяти и быстрый поиск — нужно запрограммировать самостоятельно, используя более сложные структуры. Такая программа называется аллокатором, и она является важной частью ОС. Но есть задачи, где нужно использовать альтернативный аллокатор.

## Преимущества кучи

Мы можем «просить» у аллокатор память произвольного размера для наших данных и освобождать её, когда она уже не нужна. Эти данные больше не привязаны к времени жизни функции На стеке просто хранится указатель на эти данные. Все объекты JS и некоторые примитивы хранятся исключительно в куче. Данные в замыкании также работают через кучу

## Недостатки кучи
Потребность в явном выделении и освобождении памяти имеет последствия. В низкоуровневых языках легко забыть освободить память или освободить её дважды — это приводит к UB. В высокоуровневых языках за освобождение отвечает сборщик мусора (GC) — подсистема рантайма, которая автоматически освобождает неиспользуемую память.

Альтернативный подход — счётчики ссылок — память освобождается сразу, как только счётчик достигает нуля, или управление памятью может быть сделано на этапе компиляции (Rust)
