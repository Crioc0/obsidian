# Связный список (Linked List)

Связный список — структура, в которой каждый элемент (узел) содержит:

- **Значение** (value)
- **Указатель на следующий элемент** (next)

Последний элемент указывает на `null`.

### Простейшая реализация на JavaScript

[](https://gist.github.com/kobezzza/067c629f996f8c9041144bc8ec16693c#%D0%BF%D1%80%D0%BE%D1%81%D1%82%D0%B5%D0%B9%D1%88%D0%B0%D1%8F-%D1%80%D0%B5%D0%B0%D0%BB%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F-%D0%BD%D0%B0-javascript)

```js
const node3 = { value: 30, next: null };
const node2 = { value: 20, next: node3 };
const node1 = { value: 10, next: node2 };

let head = node1;

// Обход списка
let current = head;
while (current !== null) {
    console.log(current.value);
    current = current.next;
}
```

### Свойства связного списка

| Операция                                   | Сложность |
| ------------------------------------------ | --------- |
| Добавление в начало                        | O(1)      |
| Удаление из начала                         | O(1)      |
| Добавление в конец (без указателя на tail) | O(n)      |
| Добавление в конец (с tail)                | O(1)      |
| Доступ по индексу                          | O(n)      |
| Поиск элемента                             | O(n)      |

## Реализация очереди на связанном списке

Для очереди нужно добавлять в конец, а удалять из начала. Поэтому потребуется:

- **head** — указатель на начало (откуда удаляем)
- **tail** — указатель на конец (куда добавляем)
- Двусвязный список (со ссылкой не только на next, но и на prev) для удобства

Двусвязный список (Doubly Linked List):

- Каждый узел имеет `prev` и `next`
- Позволяет эффективно удалять последний элемент (не нужно искать предыдущий обходом)

**Операции:**

- `push` (добавление в конец) — O(1)
- `shift` (удаление из начала) — O(1)

## Бенчмарк: массив vs связный список

**Результаты (на примере обхода и суммирования элементов):**

- Массив: 1x (базовый)
- Связный список: в 2 раза медленнее

**Причина — локальность данных:**

- В массиве элементы лежат рядом и попадают в кэш-линии
- В связном списке узлы разбросаны по памяти, каждый следующий — это промах кэша

## Вопрос: массив объектов — это то же самое?

Нет, не то же самое. В массиве объектов хранятся **указатели** на сами объекты. Указатели лежат рядом в массиве и хорошо попадают в кэш. В связном списке нужно сначала прочитать указатель на следующий узел, а затем пойти по нему — два промаха кэша.

## Использование связного списка на практике

В чистом виде связный список в продакшен-коде используется **редко** из-за плохой локальности и промахов кэша.

### Но связанный список — фундаментальная структура

Он служит основой для других структур данных:

**Пример: Unrolled Linked List (связанный список массивов)**

Каждый узел хранит не один элемент, а **массив элементов** (например, по 64 штуки). Это даёт:

- Лучшую локальность (в кэш попадает целый массив элементов)
- Меньше накладных расходов на указатели (узлов меньше)
- Рост без копирования (новый узел просто добавляется в список)

**Бенчмарк unrolled linked list:** разница с массивом всего 10-15%, а не 2x.

## Когда что использовать

| Сценарий                                          | Лучшая структура                 | Почему                                                  |
| ------------------------------------------------- | -------------------------------- | ------------------------------------------------------- |
| **Размер известен заранее**                       | Массив                           | Максимальная производительность, нет накладных расходов |
| **Нужен быстрый доступ по индексу**               | Массив                           | O(1) против O(n)                                        |
| **Частые вставки/удаления в середине**            | Связный список                   | O(1) против O(n)                                        |
| **Частое добавление в конец (особенно с ростом)** | Вектор (амортизированный массив) | Амортизированная O(1)                                   |
| **Частое добавление в начало или оба конца**      | Кольцевой буфер / Дек            | O(1) для обоих концов                                   |
| **Непрерывный рост без копирования**              | Unrolled linked list             | Нет релокаций, хорошая локальность                      |
| **Встраиваемая система без динамической памяти**  | Фиксированный кольцевой буфер    | Предсказуемость, нет аллокаций                          |
