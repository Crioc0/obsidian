# Массив как объект в JS

В JavaScript массив — это объект с числовыми индексами, но внутренняя реализация сложнее и зависит от движка.

**Векторное хранение (backing store):**

Независимо от наличия дырок, большинство современных движков (V8, SpiderMonkey) хранят элементы массива в **векторе** — непрерывном буфере памяти, как у C++-подобных массивов. Разница лишь в том, что для «дырок» используется специальное значение-маркер (`hole`).

```js
// Плотный массив — все слоты заполнены
const dense = [1, 2, 3, 4];
// Вектор: [1, 2, 3, 4]

// Разреженный массив с дыркой
const sparse = [1, , 3];
// Вектор: [1, hole, 3]  — память всё равно выделена под 3 слота
// hole — специальное значение, означающее "пусто"
```

**Когда массив может перестать быть вектором:**

- **Слишком большая дырявость** — если массив имеет очень большой размер, но лишь несколько заполненных элементов ( например, `arr[1000000] = 42`), движок может переключиться на хэш-таблицу, чтобы не выделять огромный непрерывный буфер под несколько значений.
- **Смешанный доступ к массиву как к объекту** — добавление нечисловых свойств ( `arr["custom"] = "value"`) обычно не влияет на хранение числовых элементов, но движок может перейти в более медленный режим.
- **Типизированные массивы (`Uint8Array` и др.)** — всегда хранятся как непрерывный буфер фиксированного размера, без переключения режимов.

```js
// Экстремально разреженный массив — может переключиться на хэш-таблицу
const huge = [];
huge[1000000] = 42;  // выделять миллион слотов ради одного значения неэффективно
```

**Вывод:** в большинстве случаев массивы в JS хранятся как векторы. Дырки не приводят к автоматическому переключению на хэш-таблицу — используется маркер `hole`. Переход на альтернативные структуры происходит только при очень сильной разреженности или после определённых операций, нарушающих оптимизации движка.
