# Управление памятью в JavaScript

JavaScript — язык с автоматической сборкой мусора (трассирующий, поколенческий, инкрементальный). Движки (V8, JavaScriptCore, SpiderMonkey) сами решают, когда запускать сборщик. Программист не управляет освобождением памяти напрямую.

### Принудительный вызов GC

В ранних версиях JavaScript принудительно запустить сборку мусора было невозможно. Сейчас в Node.js есть флаг для запуска GC (при запуске с `--expose-gc`), а также в некоторых браузерных окружениях (но не в стандарте).

```js
// Node.js с флагом --expose-gc
if (global.gc) {
    global.gc();
    console.log('GC вызван принудительно');
}
```

Использовать принудительный GC на практике почти никогда не нужно. Это полезно только для тестирования и бенчмарков.

### FinalizationRegistry — отслеживание уничтожения объектов

`FinalizationRegistry` позволяет зарегистрировать колбэк, который выполнится **после** того, как объект был собран сборщиком мусора. Это **не** деструктор и **не** детерминированное освобождение ресурсов.

```js
const registry = new FinalizationRegistry((heldValue) => {
    console.log(`Объект с ${heldValue} был уничтожен GC`);
});

let obj = {data: 42};
registry.register(obj, "пользовательские данные");

obj = null; // объект стал недостижим, в какой-то момент GC вызовет колбэк
```

**Важно:** FinalizationRegistry не гарантирует своевременного выполнения. Его нельзя использовать для критических ресурсов вроде закрытия файлов.

### using и Symbol.dispose (Disposable объекты)

Нововведение в JavaScript (ES2024, доступно в современных движках) — `using` для явного управления ресурсами. Идея напоминает RAII или `using` в C#.

```js
const getResource = () => ({
    [Symbol.dispose]() {
        console.log('Ресурс освобождён');
    },
    doWork() {
        console.log('Работаю');
    }
});

{
    using resource = getResource();
    resource.doWork();
} // здесь автоматически вызовется resource[Symbol.dispose]()
```

`using` не имеет отношения к сборщику мусора — это синтаксический сахар для блочного управления временем жизни. Отлично подходит для файловых дескрипторов, соединений с БД, таймеров.

### Слабые ссылки

Обычные ссылки в JavaScript **сильные** — они не дают сборщику удалить объект. **Слабые ссылки (WeakRef)** не препятствуют сборке. При этом доступ к объекту через `WeakRef` может вернуть `undefined`, если объект уже собран.

```js
let obj = {name: "important"};
const weakRef = new WeakRef(obj);

obj = null; // объект может быть собран GC

// позже, когда нужно получить объект
const restored = weakRef.deref();
if (restored) {
    console.log(restored.name);
} else {
    console.log("Объект уже уничтожен");
}
```

Слабые ссылки нужны для **кешей с автоматическим вытеснением**, для предотвращения утечек в паттерне «наблюдатель». Также существуют `WeakMap` и `WeakSet`, где ключи — слабые ссылки.
