# Map и Set
ES2015 ввёл `Map` и `Set` — специализированные структуры для ассоциативных коллекций, которые во многих сценариях удобнее и предсказуемее обычных объектов.

### Проблемы объектов как ассоциативных массивов


Обычные объекты JavaScript имеют ряд особенностей, которые делают их неидеальными для использования в качестве чистых словарей:

**1. Наследование от прототипа**

Объекты наследуют свойства из цепочки прототипов. Это значит, что даже пустой объект уже содержит встроенные свойства и методы, такие как `toString`, `valueOf`, `constructor` и другие.

```js
const dict = {};
console.log(dict["toString"]); // function toString() { [native code] }
// Ключ "toString" существует, даже если вы его не добавляли!
```

Это приводит к неожиданным коллизиям ключей. Если пользователь введёт ключ `"toString"`, `"valueOf"`, `"hasOwnProperty"`, он может случайно переопределить встроенные методы или получить неожиданное поведение.

**2. Символы как ключи**

Символы — уникальные и не перечисляемые ключи. Они не конфликтуют со строковыми ключами, но могут усложнить итерацию и отладку.

```js
const sym = Symbol("id");
const obj = {
    [sym]: 42,
    normal: "value"
};

console.log(Object.keys(obj)); // ["normal"] — символы не попадают
console.log(Object.getOwnPropertySymbols(obj)); // [Symbol(id)]
// Нужно два разных метода, чтобы получить все ключи
```

**3. Непредсказуемый порядок итерации**

Хотя современные спецификации определяют порядок перечисления строковых свойств объекта, он сложный и неинтуитивный:

- Целочисленные индексы (в возрастающем порядке).
- Строковые ключи (в порядке добавления).
- Символьные ключи (в порядке добавления).

```js
const obj = {};
obj["2"] = "два";
obj["3"] = "три";
obj["1"] = "один";
obj["a"] = "а";
obj["b"] = "б";

console.log(Object.keys(obj)); // ["1", "2", "3", "a", "b"]
// Числовые индексы всегда идут первыми и сортируются!
```

### Почему Map проще и предсказуемее

`Map` решает все эти проблемы:

**1. Нет прототипа**

`Map` не наследует свойства от прототипа. Ключи живут в изолированном хранилище и не конфликтуют с методами самого `Map`.

```js
const map = new Map();
console.log(map.get("toString")); // undefined — нет конфликта
map.set("toString", "кастомное значение");
console.log(map.get("toString")); // "кастомное значение" — работает предсказуемо
```

**2. Равная работа со всеми типами ключей**

`Map` одинаково хорошо работает со строками, числами, символами и объектами, используя единый алгоритм сравнения `SameValueZero`.

```js
const map = new Map();
map.set(1, "число");
map.set("1", "строка");
map.set(Symbol("id"), "символ");
console.log(map.size); // 3 — все ключи различны
```

**3. Гарантированный порядок вставки**

`Map` сохраняет порядок, в котором ключи были добавлены, без каких-либо исключений. Никакой специальной обработки для числовых индексов.

```js
const map = new Map();
map.set("2", "два");
map.set("3", "три");
map.set("1", "один");
map.set("a", "а");
map.set("b", "б");

console.log([...map.keys()]); // ["2", "3", "1", "a", "b"] — порядок вставки
```

**4. Простая итерация**

`Map` предоставляет единые и предсказуемые методы для итерации: `keys()`, `values()`, `entries()` и поддержку `for...of`.

### Другие преимущества Map

[](https://gist.github.com/kobezzza/8fd42898c4a5d77817e0b8cbee5759b2#%D0%B4%D1%80%D1%83%D0%B3%D0%B8%D0%B5-%D0%BF%D1%80%D0%B5%D0%B8%D0%BC%D1%83%D1%89%D0%B5%D1%81%D1%82%D0%B2%D0%B0-map)

- **Производительность** — при частом добавлении и удалении свойств объекты могут переключаться в медленный «словарный режим». `Map` оптимизирован для динамических операций и сохраняет стабильную производительность.
- **Любые типы ключей** — объекты, функции, примитивы — всё может быть ключом в `Map`. Объекты требуют строковые или символьные ключи.
- **Размер коллекции** — у `Map` есть свойство `size`, которое легко получить. У объектов нужно использовать `Object.keys(obj).length`.
- **Безопасность** — отсутствие прототипных свойств исключает атаки через переопределение прототипа (`__proto__`).

### Когда использовать объекты

[](https://gist.github.com/kobezzza/8fd42898c4a5d77817e0b8cbee5759b2#%D0%BA%D0%BE%D0%B3%D0%B4%D0%B0-%D0%B8%D1%81%D0%BF%D0%BE%D0%BB%D1%8C%D0%B7%D0%BE%D0%B2%D0%B0%D1%82%D1%8C-%D0%BE%D0%B1%D1%8A%D0%B5%D0%BA%D1%82%D1%8B)

Несмотря на преимущества `Map`, обычные объекты остаются лучшим выбором в некоторых сценариях:

- **Работа с JSON** — объекты сериализуются и парсятся «из коробки». `Map` требует ручной конвертации.
- **Фиксированная схема** — когда набор свойств известен заранее и не меняется. Объекты могут использовать оптимизации скрытых классов.
- **Краткость и читаемость** — для простых статических структур точечная нотация (`obj.key`) удобнее вызовов методов ( `map.get("key")`).
- **Передача в API** — многие встроенные функции и библиотеки ожидают обычные объекты.

### Сравнительная таблица

[](https://gist.github.com/kobezzza/8fd42898c4a5d77817e0b8cbee5759b2#%D1%81%D1%80%D0%B0%D0%B2%D0%BD%D0%B8%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D0%B0%D1%8F-%D1%82%D0%B0%D0%B1%D0%BB%D0%B8%D1%86%D0%B0)

|Критерий|Object|Map|
|---|---|---|
|Типы ключей|строки и символы|любые|
|Прототип|есть (наследство)|нет|
|Конфликт с `toString`, `__proto__`|да|нет|
|Порядок итерации|сложный (числовые индексы особо)|порядок вставки|
|Безопасность ключей|уязвим к прототипным атакам|безопасен|
|Производительность при частых изменениях|переключается в словарь|стабильна|
|JSON (`stringify`/`parse`)|из коробки|нет (нужна конвертация)|
|Синтаксис доступа|`obj.key` или `obj["key"]`|`map.get(key)` / `map.set(key, value)`|
|Размер коллекции|`Object.keys(obj).length`|`map.size`|
|Итерация|`Object.keys()`, `for...in`|`map.keys()`, `map.values()`, `for...of`|
|Оптимизация скрытых классов|да (при фиксированной структуре)|нет (всегда хэш-таблица)|
