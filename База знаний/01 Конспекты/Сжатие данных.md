# Сжатие данных

Сжатие (gzip, brotli, zstd) действительно может значительно уменьшить разницу в размере между текстовыми и бинарными форматами. Однако есть важные нюансы, которые делают выбор формата всё ещё актуальным.

### Как сжатие работает

Алгоритмы сжатия ищут **повторяющиеся паттерны** и заменяют их ссылками. JSON с его повторяющимися ключами (`"name"`, `"age"`, `"city"`) сжимается очень хорошо — иногда лучше, чем бинарные форматы.

**Парадокс:** Бинарный формат может сжиматься **хуже** текстового, потому что в бинарных данных меньше повторяющихся паттернов (байты разнороднее, чем текст).

### Нюанс 1: Степень сжатия зависит от данных

|Тип данных|JSON сырой|JSON+gzip|MessagePack сырой|MP+gzip|
|---|---|---|---|---|
|**Много повторяющихся ключей** (JSON API)|100%|15%|70%|12%|
|**Массив чисел (случайные)**|100%|85%|40%|35%|
|**Массив чисел (последовательные)**|100%|20%|40%|15%|
|**Текстовые данные (логи)**|100%|25%|80%|22%|
|**Уже сжатые данные (изображения)**|100%|98%|100%|98%|

### Нюанс 2: Нагрузка на процессор (CPU cost)

Сжатие — это **компромисс между размером и CPU**. Сильное сжатие требует больше процессорного времени.

**Сравнение CPU затрат:**

|Операция|CPU затраты|Когда использовать|
|---|---|---|
|**JSON.parse (без сжатия)**|Низкие|Отладка, маленькие данные|
|**gzip decompress + JSON.parse**|Высокие|Большие данные по медленной сети|
|**MessagePack.decode (без сжатия)**|Низкие|Быстрая сеть, высокая нагрузка|
|**Brotli decompress +**|Очень высокие|Кэшируемые статические ассеты|

### Нюанс 3: Статические vs динамические данные

Это ключевой момент при выборе формата и стратегии сжатия.

**Статические данные (изменяются редко):**

- Хранятся долго, запрашиваются многократно
- Можно сжать один раз и закэшировать
- Степень сжатия важнее скорости сжатия

**Динамические данные (меняются каждый запрос):**

- Сжимать каждый раз дорого (CPU)
- Лучше использовать компактный бинарный формат без сжатия
- Или отказаться от сжатия вообще ради скорости

### Нюанс 4: Сетевая пропускная способность vs CPU

**Матрица выбора стратегии:**

|Ситуация|CPU свободен|CPU нагружен|
|---|---|---|
|**Сеть медленная**|Сжимать всё (JSON+gzip)|Использовать бинарный формат (MessagePack)|
|**Сеть быстрая**|Отдавать без сжатия (JSON)|Отдавать без сжатия (MessagePack)|

### Нюанс 5: Тяжело сжимаемые данные

Некоторые данные **почти не сжимаются**:

1. **Уже сжатые данные** — JPEG, PNG, MP4, MP3 (сжатие не имеет смысла)
2. **Криптографические данные** — шифротекст выглядит как случайный шум
3. **Высокоэнтропийные данные** — уникальные идентификаторы (UUID), хеши
4. **Короткие сообщения** — накладные расходы на алгоритм сжатия превышают выгоду

### Сравнительная таблица: JSON+gzip vs MessagePack (без сжатия)

|Сценарий|JSON+gzip|MessagePack|Победитель|
|---|---|---|---|
|**Короткие API запросы (< 1 KB)**|CPU оверхед (gzip)|✅ Быстро, без оверхэда|MessagePack|
|**Большие JSON с паттернами (> 100 KB)**|✅ Отличное сжатие|Хорошо, но сжатие не нужно|JSON+gzip (если CPU свободен)|
|**Высокая нагрузка (10k+ RPS)**|CPU станет узким местом|✅ Низкий CPU|MessagePack|
|**Медленная сеть, редкие запросы**|✅ Максимальная экономия|Хорошо, но хуже|JSON+gzip|
|**Случайные/уникальные данные**|Сжатие бесполезно|✅ Компактнее изначально|MessagePack|
|**Логи (огромные файлы)**|❌ Нужно читать и сжимать|✅ Потоковая запись без сжатия|MessagePack|

### Главные выводы по сжатию

1. **Сжатие НЕ делает все форматы одинаковыми.** Для некоторых типов данных разница сохраняется (случайные числа, шифротекст).
2. **Есть trade-off между CPU и размером.** Сильное сжатие экономит трафик, но грузит процессор. Выбор зависит от того, что у вас дефицит — CPU или сеть.
3. **Статические данные** — отлично подходят для сильного сжатия (Brotli на максимальных настройках). Сжимаем один раз — используем много раз.
4. **Динамические данные** — MessagePack без сжатия часто лучше, чем JSON + gzip, особенно под высокой нагрузкой.
5. **Всегда измеряйте.** Степень сжатия сильно зависит от реальных данных. Протестируйте на своих данных, прежде чем принимать решение.
6. **Гибридный подход.** Никто не запрещает использовать MessagePack **и** сжатие. Просто включите сжатие на уровне веб-сервера (nginx, CloudFlare) и не думайте об этом — они сами решат, когда и что сжимать.
