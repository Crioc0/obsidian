Каждой инструкции соответствует опкод. Процессор интерпретирует опкод как команду к действию. 

Языки программирования позволяют упрощать написание кода, переводя работу с бинарного языка на понятный читаемый язык.

Программа представляет собой поток двоичных чисел. Такое представление программы называется машинным кодом(реже байткодом).

Можно упростить, используя 16 сиcтему счисления. Битам, отвечающим за операции нужно дать символические имена. Этот вариант непонятен вычислителю - требуется переводчик - программа, преобразующая в машинный код.

Ассемблер - это программа транслятор которая переводит читаемый код в машинный. Язык ассемблера транслируется 1 к 1 в машинный код под конкретную архитектуру. 

ОС создает абстракцию над железом. Разработчик работает с программным интерфейсом ОС, а не компьютером напрямую. Каждая ОС вводит свой формат исполняемых файлов. Исполнением программы занимается именно компьютер, ОС выступает в роли менеджера. При трансляции ассемблером нужно указать на какую ОС нужен исполняемый файл.

В языках высокого уровня не работает с ячейками памяти напрямую, а используются переменные. Появляются типы и строгие контракты c ними. Появляются подпрограммы. Так же нет привязки к определенной архитектуре, можно перегнать в разные процессоры.

Компиляция - транслирование программы в машинный код под конкретную платформу, программа, которая это делает -компилятор. Компилятор может проверить ошибки и делает различные оптимизации. Компилятор не исполняет файл с исходным кодом, только преобразует в машинный.

Формат исполняемого файла - строго описанная структура

Интерпретатор - программа, которая принимает исходный код на языке программирования и немедленно начинает его исполнять. Такой подход называется интерпретацией. Теперь не нужна явная фаза компиляции. Без интерпретатора программа не запустится. Интерпретатор сам запускает программу.

Наивная интерпретация на порядок медленнее скомпилированной версии.

Чтобы не парсить инструкции из строки, можно транслировать исходный код в удобный формат - специально разработанный под задачу бинарный код - байткод. Байткод нативно не поддерживается процессором, нужен интерпретатор. Интерпретатор байткода называется виртуальной машиной. 

Байткод может кэшироваться и при последующих запусках будет браться из кэша.

Компилятор может производить универсальный байткод для всех архитектур, который потом будет исполняться виртуальной машиной(Java, C#). При исполнении не нужно делать парсинг исходного кода. Опционально поддерживается многими интерпретаторами

Байт код может быть преобразован в машинный в процессе выполнения программы. Есть две стратегии - преобразовать весь байт код в машинный перед непосредственным выполнением программы(AOT). Так работает WebAssembly. Вторая стратегия - преобразовывать отдельные части в машинный код во время работы (JIT)

JIT компилятор работает параллельно с исполнением программы. Горячие фрагменты постепенно  компилируются в машинные кода. JIT можно прогревать, чтобы оптимизировать некоторые тяжелые операции. 
Не каждая JS функция может быть скомпилирована JIT, так как JS динамическая типизация. Чем строже код, тем больше шансов на успех.

Все, что необходимо для запуска программы : интерпретатор, сборщик мусора, Jit компилятор, отладчик и прочее называется рантаймом.

Система правил как работать с типами называется типизацией.

Виды типизации: 
Явная / неявная / гибридная
Сильная (строгая) / слабая (нестрогая)
Статическая / динамическая
Структурная / номинальная / утиная
